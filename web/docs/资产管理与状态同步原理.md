# 资产管理与状态同步原理

本文对应 v1.0.2。需要区分三种数据：磁盘上的媒体文件、随工作流保存的任务与历史索引、仅在浏览器中存在的队列及组件缓存。

## 生成结果如何保存

1. `api_injector.js` 监听 `executed`，通过 `prompt_id` 查找发起任务时保存的工作区、输入快照和输出目标。
2. 图片、视频、音频和模型等通过 `/clab/copy_temp_asset` 复制到 `output/CLab` 或自定义归档目录；文本通过 `/clab/save_text` 保存为文件。文件名前缀默认 `pix`。
3. 后端返回归档文件名、子目录和类型，前端建立 `/view` 地址，追加到对应输出模块历史，同时关联输入快照、运行编号及媒体信息。
4. 更新任务数据并写回配置节点，仅刷新受影响模块。文件异步转存期间保留任务映射，不能提前释放后续回传需要的数据。
5. 用户保存 ComfyUI 工作流后，配置节点中的索引随工作流 JSON 保存。复制工作流到另一台电脑并不会自动复制引用的媒体文件。

归档不是“把所有结果先写入临时 URL，再一律替换”的固定流程；成功返回的文件才建立可用历史。网络、磁盘和抓取错误仍可能导致某次结果未能入库。

开启保留原临时文件时不删除原件；关闭后按后端规则清理原临时文件。模型的外置贴图、材质及缓冲资源按相对引用关系归档，缺失资源会提示。

## 配置节点与内存

`StateManager` 将 schema v4 的 `workspaces[]`、任务、绑定、生成历史、归档及需保存的视图设置编码到 `CLab_SystemConfig` 的 `scenes_data` 数据值中。

`config_storage.js` 将数据取值与前端文本框显示分开：节点仍持有完整配置，文本框只显示简短说明，避免对大型 JSON 反复做文字布局。不是把配置改成只存浏览器内存，也不是将全部数据移到 Python 后台。

- 普通内容保存合并约 250ms，视图保存等待约 200ms 空闲。
- 未变化工作区复用序列化结果，保存时仍组合成完整配置。
- 运行、关闭面板、保存工作流、页面离开及撤销等关键时刻补存。
- 未保存工作流前，配置节点的修改还不等于已经写入磁盘工作流文件。
- 撤销历史、待提交执行队列、隐藏组件／播放器缓存不作为完整配置写入工作流。

## 加载与局部呈现

载入工作流后，读取配置节点，迁移旧结构并恢复各工作区。旧通道转换为独立工作区。当前活动工作区的数据镜像到 `state.cards`，其他工作区的数据仍在 `workspaces[]` 中。

打开面板先绘制界面，再分批建立当前视图附近的卡片、控件及媒体。参数表按行列、矩阵按可见格子及 Z 层加载；不会为所有历史一次性建立完整播放器。媒体地址通过 ComfyUI 的 `/view` 读取磁盘文件，文件不存在时显示失效状态。

最近卡片、普通组件、音视频和 3D 的默认缓存上限为 8／64／2／1，可以在设置中调整；隐藏音视频和 3D 约 30 秒到期后也会回收资源。缓存淘汰不删除任务、参数或生成记录。

## 历史和参数的对应关系

输出模块同时维护媒体历史、文本记录、输入快照及运行元数据。增加、删除、排序、容量裁剪时，相关信息必须一同调整，不能只修改 `history` URL 数组。

- 同一次任务的输出使用同一运行编号关联。
- 历史切换默认按快照恢复输入，可在设置中关闭回填。
- 未记录快照的旧结果不能用当前输入值冒充生成参数。
- 已归档任务仍可接收迟到结果；从归档恢复复用原任务和历史。

## 数据维护的三种用途

### 清理失效记录

统一维护面板针对当前活动工作区。非文本媒体通常用不缓存的 `HEAD` 请求检查，文本还会检查读取状态。明确不存在的文件才移除历史引用及对应快照；连接中断不应直接当作文件已删除。

输出模块右键的局部清理与维护面板的工作区清理范围不同。清理不是删除有效的物理文件。

### 重新同步记录

给历史及当前媒体地址刷新时间戳，并重新加载文本与媒体，用于查看外部软件覆盖后的文件。相同文件仍保持原任务归属；不会重新运行工作流或凭空补回已删除的文件。

### 已归档任务

任务卡片删除、参数表删行、矩阵组合退出活动区等通过任务归档逻辑保留有内容的任务。维护面板可恢复或删除归档引用；空草稿和未运行、未修改的矩阵占位任务可以直接移除。删除归档不删除对应磁盘媒体。

## 下载、整理与备份

- **下载媒体**：将所选原始文件打包 ZIP，或选择一次本地文件夹批量保存。
- **收集整理**：调用 `/clab/organize_files` 的复制操作，按任务、模块、历史编号保存到归档目录的子文件夹，不重写原模块归属。
- **版式导出**：PNG 是排版后的静态画面；HTML 可携带媒体和历史用于离线查看；Excel 保留表格与可用嵌入图片。
- **工作流备份**：保存工作流及媒体目录。PNG、HTML、JSON 数据表或浏览器缓存均不能完整替代可运行工作流。
