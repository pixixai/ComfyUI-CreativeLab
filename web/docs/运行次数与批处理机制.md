# 运行次数与批处理机制

本文对应 v1.0.2，说明三种工作区如何选择任务、循环排队、保存结果及主动打断。配置节点保存任务和历史，不是后台执行队列。

## 默认运行范围

| 工作区 | 没有选择时点击运行 | 有选择时点击运行 | 运行全部 |
| --- | --- | --- | --- |
| 任务卡片 | 全部有输出模块的任务 | 所选卡片／输入模块所属任务；选中输出模块时只执行对应输出 | 当前工作区全部输出任务 |
| 参数表 | 当前表全部有效任务行 | 所选行或单元格所属的有效任务行及其已绑定输出；仅选空草稿不运行其他任务 | 当前表全部有效任务行 |
| XY 矩阵 | 当前活动 Z 层，未启用 Z 时为整个矩阵 | 当前层的所选格子 | 全部 Z 层，不受局部选择限制 |

XY 按工作区设置的 X 优先或 Y 优先排列，跨层运行时按 Z 取值顺序逐层处理。

## 运行次数

共用工具栏从左至右为「次数、运行＋范围菜单、打断运行」。次数范围为 1～999，作用于当次选定的运行范围。

循环按范围交叉展开。任务 A、B 运行三次时为 `A → B → A → B → A → B`，不是先跑完 A 三次再处理 B。展开时复制每个任务描述对象；展开运算符是浅复制，并不等于深复制工作流。

## 点击时快照与延迟编译

1. 各模式计算基础任务描述，包含 `cardId` 和 `previewAreaIds`。
2. `window.CLab.executeTasks()` 为整个批次冻结输入值、绑定、输出目标、附加记录参数和所属工作区，预留当次历史运行顺序。
3. 待提交任务保存在浏览器页面内存中。只有进入提交窗口时，才调用原生图谱编译、注入冻结参数并剪除无关输出依赖。
4. 请求被接受后，以 `prompt_id` 映射回原任务；结果保存到发起时的工作区，即使后来切换或复制了工作区。

快照保护插件输入和绑定；不要将它理解为可在生成期间随意删除、重构原工作流节点的完整工作流备份。

## 有界提交与补位

三种工作区共用一个提交窗口。默认最多保留五个未完成的 CLab 提交，约为「一个运行＋四个等待」。编译中的请求也占一个名额，编译仍串行进行，避免多任务注入互相覆盖。

- 设置 → 性能与媒体播放 → 提前排队任务数，范围 1～10，默认 4。
- 引擎完成、失败或中断一项后释放名额，并自动补交下一项。
- 调大立即补位；调小等待现有提交消化，不删除已提交任务。
- 限制只计算本插件的任务，不控制其他客户端或原生 ComfyUI 队列。
- 已完成任务的文件转存可继续进行，不必等转存完成才提交下一项；任务映射保留至结果持久化结束。

剩余任务只保存必要的参数和目标，不提前编译全部完整请求。这主要减少提交阶段和等待队列的内存占用，不改变正在生成的模型与显存需求。

## 报错与主动打断

### 异常阻断

开启「连续运行异常阻断」时，校验或运行失败取消对应批次尚未提交及已提交的后续等待任务；其他批次不受影响。关闭时跳过失败项继续补交。运行错误显示红色；正常卡片进度条、参数表任务行和矩阵格子使用彩虹进度反馈。

### 打断运行

1. 插件有待运行任务时，右侧打断按钮变红。
2. 点击后立即标记插件各工作区批次取消，清空本地待提交任务。
3. 按 prompt ID 删除后台等待项，并定向打断已运行项；提交途中才返回的请求也按取消标记处理。
4. 取消请求处理中暂不接收新批次，重复点击共用同一次请求。失败会提示并保留任务映射，允许重试。

打断请求优先发送，不被历史恢复或文件转存阻塞。已生成或正在归档的有效结果保留，不删除磁盘文件。实际生成停止仍取决于后台当前运算响应中断的时机。

### 原生队列与重连

在 ComfyUI 清空等待队列时，同时停止插件本地后续补交，当前运行项可继续完成。重连或队列编辑时，按 `/queue` 与对应 `/history` 核对任务、补收漏掉的结果；正常长任务不需要持续轮询整条队列。

关闭 CLab 面板继续运行和补交。刷新、关闭浏览器页面会丢失尚未提交的队列，配置节点不会自动恢复这部分执行计划。已被后台接受的任务则由 ComfyUI 管理。

## 结果与撤销

结果附带运行编号、输入快照和当次参与输出集合。同一任务多个输出按运行编号关联，不依赖彼此的历史条数。只运行某个输出模块时，不伪造其他输出的同轮结果。

运行不是内容撤销步骤；撤销参数、排版或绑定不会取消队列，也不会删除后来生成的媒体。停止执行请使用打断按钮。
