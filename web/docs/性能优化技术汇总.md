# 性能优化技术汇总

本文以 v1.0.3（2026-11-15）为基线，汇总插件已实现的性能机制。与按时间记录的 [局部微创更新重构记录](局部微创更新重构记录.md) 不同，本文按当前职责组织；早期实现与本文冲突时，以当前代码和本文说明为准。

## 优化目标与边界

优化主要减少浏览器中的重复计算、页面元素、布局测量、媒体实例及预提交请求，改善打开、选择、编辑、滚动、缩放、切层和跳转。它不会减少生成模型本身需要的推理时间、模型内存或显存。

所有任务、绑定、参数与生成历史仍完整保存在数据模型中。按需加载只控制界面和播放器是否存在，不用页面上当前挂载的元素决定运行、批量选择、克隆或归档范围。

## 局部更新与 DOM 复用

- 单模块改变优先原位更新值、标题、绑定摘要或媒体状态；只有组件结构确实改变时才替换对应模块。
- 移动卡片、模块和排序使用现有 DOM，保留媒体、焦点、输入位置与滚动状态，避免无关组件重新初始化。
- 选择只更新前后选区的差异；参数表进入／退出编辑只同步相关单元格，避免选择时再次同步全部任务和参数。
- 工具栏外观相同时复用按钮，再绑定当前操作目标。运行进度通过轻量状态事件更新，不触发全列表重绘。
- 结构核对以稳定 ID 和集合定位对象，减少重复搜索整份任务列表；未新增组件时不重复装配整组事件。

主要入口：`comp_modulearea.js`、`ui_selection.js`、`module_lifecycle.js`、`comp_toolbar.js`。保存与渲染分开，不能为了保存一个值再次执行完整列表重建。

## 三种工作区的按需加载

### 任务卡片

`card_window.js` 根据滚动位置计算实际卡片窗口，只保留当前视图、左右缓冲及必须暂留的编辑／上传／拖拽对象。默认左右各约 5 张缓冲，可在设置中修改。

窗口外任务不需要长期保留卡片和模块外框。窗口内进一步按模块可见范围装载完整组件；缓冲区优先保留布局和轻量结构，避免同时初始化所有播放器。Shift 跨屏选择、拖拽、克隆、运行和撤销仍根据完整任务数据计算。

### 参数表

完整行列、尺寸和选择来自表格模型；可见行列及附近才装载完整编辑控件与媒体。当前实现仍保留表格结构和部分占位单元格，不等于整个表格只存在屏幕内几格 DOM。

当前可见区域的新取值成组显示，避免数值逐行填入；已有编辑器继续复用。行列尺寸、外观和选区更新不无条件重建媒体。表格输入、上传和草稿提升继续使用原始任务／模块 ID。

### XY 矩阵

缩放和平移合并到动画帧，视图变换优先改变已有画布结构，不随鼠标每个事件重新生成任务。未显示的 Z 层不初始化完整媒体；缩小时使用轻量图像／文字摘要，放大、选中及进入可见范围后再装载详细组件。

图片／视频尺寸事件合并，只有中位宽高比实际改变时才重新布局。完整矩阵数据及历史保留；切层、缩放不是删除任务。卡片／模块较多时由共同的 `viewport_components.js` 控制装载与回收。

## 打开与分帧调度

`panel_loading.js` 先让面板外壳绘制，再核对工具栏、工作区与当前内容。新创建的模块直接使用当前数据，不立即再刷新一遍；重新打开时核对原有控件，保留可复用内容。

`frame_work.js` 按实际耗时调度，不再固定每帧最多两个作业。普通视口工作预算约 6ms，跳转目标预备约 2ms；简单作业可以同帧完成，复杂组跨帧继续。单个同步函数仍必须执行结束，预算不是强制抢占上限。

- 卡片先生成可见内容、测量文本，并补齐因高度变化而新进入视图的模块，再成组显示。
- 参数表可见区域的新单元格成组呈现，保留现有控件，不让新数据逐行冒出。
- 音视频和 3D 先显示稳定结构；普通内容完成一次绘制后，再启动播放器和查看器。
- 工作区改变、关闭面板或改换跳转目标会取消旧批次；执行前核对所属工作区、容器和模块，防止迟到工作写进新界面。
- 尚未激活的预备结构保存布局签名，数据或宽度变化后重新准备。

## 滚动与远距离定位

卡片滚轮采用连续平滑位移，取消一格一张和连续加速。一次连续滚动期间锁定原滚动区域，避免指针轻微移入卡片后意外滚动其内部。

`card_navigation.js` 与 `card_navigation_plan.js` 区分近距离与远距离：近距离平滑滚动；远距离先滚动小段，跨过中间任务，再从目标附近滚动至目标。动画期间只按小预算准备目标可见卡片的普通控件，沿途及目标缓冲区保持轻量外框；抵达后恢复通常的缓冲和重媒体加载。

新的目标、滚轮、按下鼠标和关闭面板都可中断原定位。运行跟随只定位必要任务；XY 批次完成后恢复原 Z 层和视角。

## 布局测量与共享资源

- `input_measure.js` 以文本、宽度、字体、行距、字距及边距等组成测量键，最多缓存 128 项高度；相同条件直接复用。大型键不长期保留，字体加载完成后清理旧结果。
- `card_layout.js` 按绑定、值、标题、宽度、媒体及显示设置判断布局是否仍有效；优先使用已知媒体尺寸，减少估算高度到真实高度的变化。
- `media_dimensions.js` 合并同一媒体 URL 的在途探测，最多保留 128 项成功尺寸结果，避免相同图片被多个模块反复独立探测。
- 共用模块生成代码、样式、图标、参数定义和尺寸结果。每个真实控件仍有独立 DOM、输入值、绑定和交互状态，不能像三维网格实例那样只占一份界面内存。

首次遇到未知图片／视频尺寸仍可能有一次布局修正。不能靠永久固定估算高度避免测量，否则会引入裁切、空白或错误滚动位置。

## 有界缓存与资源回收

| 缓存类别 | 默认上限 | 作用 |
| --- | --- | --- |
| 最近卡片 | 8 张 | 返回最近访问卡片时复用外框和已有控件 |
| 普通组件 | 64 个 | 减少文本、选项等控件反复创建 |
| 隐藏音视频 | 2 个 | 短暂保留播放器，返回时复用 |
| 隐藏 3D | 1 个 | 短暂保留查看器，控制 GPU 资源占用 |

上限可在「性能与媒体播放」设置中调整，0 表示关闭对应缓存。各类独立淘汰，调低上限立即回收超出部分；音视频和 3D 另有约 30 秒隐藏失效时间。

移出视图时暂停播放和绘制，保存播放位置、音量、速度、视角、动画及滚动状态。淘汰时清理媒体源、监听、模型、贴图和 WebGL 等资源；返回时用保留的轻量状态恢复新实例。缓存命中优先于回收旧视图，避免小缓存先淘汰即将返回的播放器。

这些缓存只存在于当前浏览器页面内存，不写进配置节点，不是磁盘缓存，也不是固定 MB 配额。关闭面板可能保留有界缓存；刷新或关闭页面会清除它。任务参数和生成历史不因缓存淘汰而删除。

## 媒体与五种预览的复用

图片缩略图使用浏览器缓存和异步解码；视频默认不自动播放，缩略图采用静帧。音视频仍可能占用解码器及 GPU 资源，不能把隐藏等同于无开销。

3D 查看器和格式加载器按需加载；静止或暂停时不持续绘制，只有可见且播放中的动画持续更新。离开、隐藏、到期和超限由共同生命周期回收，避免无限创建 WebGL 上下文。

浏览／比较调整来源、排序、侧栏和视角时保留当前媒体；比较复用两路控件与同步状态。明细表字段／样式修改优先只更新数据区，保留封面和内容媒体。参数表与矩阵预览继续使用对应工作区的布局和媒体机制，避免维护两套彼此不同的组件。

## 保存、配置节点与撤销

普通保存约 250ms 合并，视图保存等待约 200ms 空闲；待写回工作区范围累积，运行、关闭面板及保存工作流等时机补存。序列化复用未变化工作区的结果，避免每次小操作重新编码全部工作区。

`config_storage.js` 将完整 JSON 保留在配置节点的数据值中，前端文本框只显示简短说明。它解决的是巨型文本框、原生历史及界面绘制开销，不意味着完整数据不占浏览器内存，或已经自动写到磁盘；仍需保存工作流。

插件内容历史按工作区隔离，工作区与预览共享所属工作区的历史。局部输入操作只重新捕获受影响任务／模块，其他大型分支复用快照；结构、绑定及批量操作仍需完整核对所属工作区。恢复结果优先原界面展示，必要时切换到能看到变化的页面。

选择、筛选、缩放、平移和历史查看不进入内容撤销；输入框内保留原生文字撤销。插件历史到顶后不会继续触发 ComfyUI 整工作流撤销，避免配置节点引起整个界面重新加载或长时间阻塞。

## 批量运行与异步结果

点击运行时冻结所选范围全部任务的输入、绑定和归属，保证后续修改不改变已计划任务；不是立刻为所有任务编译完整请求。

`execution_queue.js` 默认控制约 1 个运行＋4 个等待，编译中的任务也占一个名额。后续任务在本地等待，名额释放再编译和提交；等待数可设为 1～10。快照与本地待运行清单仍占内存，但不再同时生成和提交百份完整工作流。

引擎完成、报错或中断释放提交名额，文件转存和参数快照保存独立完成，不拖慢下一项补位。正常运行不轮询完整队列，断线重连等场景再按 prompt ID 核对队列和历史。原生任务不计入插件提交上限。

打断先清空本地后续计划，再定向取消插件已提交任务；迟到的提交返回仍按取消状态处理。已经产生的结果和归档不删除。关闭面板继续补交，关闭／刷新页面不恢复本地尚未提交的队列。

## 导出时的内存控制

PNG 将离屏媒体准备为静帧，分块绘制并使用流式 PNG 编码，减少一次分配超大 Canvas 和整图重复副本的开销；不用扩大实时视口来强行加载全部播放器。下载使用原文件，版式 PNG 则按当前展示布局渲染，两者不能混为同一条流程。

大图仍受浏览器、内存、图片编码及剪贴板能力限制。分块不代表无限尺寸，也不能保证 10 倍导出始终成功；过大时降低倍数、减少来源或改用 HTML。HTML 离线资源打包、Excel 内嵌图片和 ZIP 压缩也会有独立的临时内存成本。

## 验证与维护

在插件目录执行 `node --test tests/*.test.mjs`。v1.0.3 共 361 项前端自动测试通过。

浏览器专项使用独立测试页面，不修改用户实际工作流。`CLAB_BROWSER_SUITE=presentation` 覆盖降低 CPU 速度后的逐帧成组显示、布局稳定、播放器延后、预备结果失效、快速开关、远距离目标预备、缓存回收、100／1000 任务的选择与拖拽等回归；其他专项入口见 [开发指南](开发指南.md)。

性能验证应同时检查首次访问、缓存命中、缓存淘汰后的返回、持续滚动、连续改换目标、关闭重开、后台结果回传及历史恢复。不能只以某一次打开耗时判断整体收益，也不能通过丢任务、历史、焦点或媒体状态换取表面流畅。

具体模型、保存与队列说明见 [资产管理与状态同步](资产管理与状态同步原理.md)、[运行次数与批处理机制](运行次数与批处理机制.md)。
